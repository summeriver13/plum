## 一、背景

策略层中依赖财务数据（Level 3）的策略涉及归母净利润、ROE、净资产、经营现金流等字段。当前 Plum 的数据层仅覆盖 Level 1（OHLCV 行情）和 Level 2（PE/PB 估值因子），缺少完整的财务数据管道。

**QMT xtdata 已提供 `get_financial_data()` API**，可直接获取利润表（Income）、资产负债表（Balance）、现金流量表（CashFlow）、每股指标（PershareIndex）四张表。但当前 `QMTConnector` 未使用这些 API。

---

## 二、需求分析

### 2.1 策略对财务列的依赖

| 因子 | 依赖的原始数据 | QMT 来源 |
|------|-------------|---------|
| 归母净利润 | `R_np_atoopc@xbx_ttm` | Income.`net_profit_excl_min_int_inc`（TTM 聚合） |
| 归母净利润同比 | 同上，时间序列计算 | 同上 + 去年同期值 |
| ROE | `R_np_atoopc@xbx_ttm` / `B_total_equity_atoopc@xbx` | PershareIndex.`du_return_on_equity`（或自行计算） |
| 净资产（BP） | `B_total_equity_atoopc@xbx` | Balance.总权益 |
| 自由现金流 | `C_ncf_from_oa@xbx_ttm` - `C_cash_paid_for_assets@xbx_ttm` | CashFlow |
| 分红率 | 分红记录 | PershareIndex 每股分红 / 收盘价 |
| 净利润率 | 净利润 / 营收 | Income 计算 |

### 2.2 输出格式

预处理后的财务数据需要以 **宽表** 形式注入因子计算流程，列名为策略层约定的中文字段：

| 输出列名 | 含义 | 更新频率 |
|---------|------|---------|
| `归母净利润` | TTM 归母净利润（元） | 每季报更新 |
| `归母净利润同比` | 归母净利润单季同比（%） | 每季报更新 |
| `归母净利润同比增速` | 归母净利润单季同比增速（%） | 每季报更新 |
| `ROE` | 净资产收益率（%，全年 TTM） | 每季报更新 |
| `ROE_np_单季` | 单季 ROE | 每季报更新 |
| `净资产` | 归母净资产（元） | 每季报更新 |
| `自由现金流` | TTM 自由现金流（元） | 每季报更新 |
| `净利润率` | 净利润 / 营收 | 每季报更新 |
| `红利因子` | 近 12 个月每股分红 / 收盘价 | 年报更新 |

## 三、架构设计

### 3.1 模块位置

```
app/data/
├── connectors/       ← 已有：qmt.py, baostock.py（Level 1+2）
├── financial/        ← 新建：Level 3 财务数据管道
│   ├── __init__.py
│   ├── fetcher.py         # 调用 xtdata API，下载/获取原始财务数据
│   ├── preprocessor.py    # 清洗：PIT 对齐 + 同比计算 + TTM 聚合
│   ├── schema.py          # 财务数据模型
│   └── store.py           # 落盘 Parquet + meta.json
├── store/            ← 已有：Parquet I/O 基础设施（可复用）
├── syncer/           ← 已有：DataSyncer 框架（可复用 FinanceSyncResult）
└── schema.py         ← 已有：Bar 数据模型
```

### 3.2 数据流

```
QMT xtdata（数据源）
    │
    │ download_financial_data()  ← 按股票列表 + 表名批量下载
    │ get_financial_data()       ← 按时间范围获取原始 DataFrame
    ▼
fetcher.py（获取层）
    │ 输入：股票列表、起止时间
    │ 输出：{stock: {table: DataFrame}} 原始财务数据字典
    ▼
preprocessor.py（清洗层）
    │  1. 按 report_time 对齐报告期（Q1/Q2/Q3/Q4）
    │  2. 计算 TTM（最近四个季度滚动求和）
    │  3. 计算单季同比/环比
    │  4. PIT 合规：按公告日期延迟 1 个交易日
    │  5. 输出标准宽表
    │ 输出：pd.DataFrame(index=[交易日期, 股票代码], columns=[因子列...])
    ▼
store.py（存储层）
    │ 复用现有 Parquet I/O 模式
    │ 按股票/年度分片存储
    │ meta.json 记录同步状态
    ▼
因子计算（Factor.compute）
    │ 通过 DataBundle 传入宽表
    │ 因子从 df.columns 读取对应列
```

### 3.3 与现有架构的关系

```
                        ┌──────────────────┐
                        │   QMTConnector   │  ← 不改动，仅提供 Level 1+2
                        └────────┬─────────┘
                                 │ Bar (OHLCV + PE/PB)
                                 ▼
┌──────────────┐       ┌──────────────────┐
│ FinancialFetcher │──▶│ FinancialStore    │  ← 新建
│ (财务数据获取)   │   │ (Parquet 落盘)    │
└──────┬───────┘       └────────┬─────────┘
       │                        │ 宽表 (日期 × 股票 × 财务列)
       │                        ▼
       │               ┌──────────────────┐
       └──────────────▶│  DataBundle      │  ← 已有，合并 Bar + 财务宽表
                       │  (因子计算输入)    │
                       └──────────────────┘
```

## 四、接口设计

### 4.1 FinancialFetcher

```python
class FinancialFetcher:
    """QMT 财务数据获取器。"""

    def download(
        self,
        stock_list: list[str],
        table_list: list[str] | None = None,
        start: str | None = None,
        end: str | None = None,
    ) -> None:
        """下载财务数据到本地 QMT 数据目录。
        
        Args:
            stock_list: QMT 格式股票列表，如 ["600035.SH", "000100.SZ"]
            table_list: 表名列表，默认全部 (Income/Balance/CashFlow/PershareIndex)
            start: 起始日期 YYYYMMDD
            end: 结束日期 YYYYMMDD
        """

    def fetch(
        self,
        stock_list: list[str],
        table_list: list[str] | None = None,
        start: str | None = None,
        end: str | None = None,
        report_type: str = "report_time",
    ) -> dict[str, dict[str, pd.DataFrame]]:
        """获取已下载的财务数据。
        
        Returns:
            {stock_code: {table_name: DataFrame}}
            DataFrame 列名为 QMT 原始英文字段
        """

    def fetch_and_preprocess(
        self,
        stock_list: list[str],
        start: str,
        end: str,
    ) -> pd.DataFrame:
        """获取并预处理为因子计算用的宽表。
        
        一步完成：下载 → 获取 → 清洗 → PIT 对齐 → 输出宽表
        
        Returns:
            MultiIndex DataFrame: (交易日期, 股票代码) → 因子列
        """
```

### 4.2 FinancialPreprocessor

```python
class FinancialPreprocessor:
    """财务数据清洗器。"""

    # QMT 原始字段 → 数据层输出列 的映射
    FIELD_MAP: dict[str, str] = {
        "net_profit_excl_min_int_inc": "归母净利润",
        "du_return_on_equity": "ROE",
        "total_equity": "净资产",
        "revenue": "营业总收入",
    }

    def to_ttm(self, df: pd.DataFrame, col: str) -> pd.Series:
        """将单季数据滚动聚合为 TTM。"""

    def calc_yoy(self, df: pd.DataFrame, col: str) -> pd.Series:
        """计算单季同比（%(本期 - 去年同期) / |去年同期|）。"""

    def align_to_trading_days(
        self,
        fin_df: pd.DataFrame,
        trading_calendar: pd.DatetimeIndex,
    ) -> pd.DataFrame:
        """PIT 对齐：将财务数据按公告日期映射到最近交易日。"""

    def process(
        self,
        raw_data: dict[str, dict[str, pd.DataFrame]],
        trading_calendar: pd.DatetimeIndex,
    ) -> pd.DataFrame:
        """主处理流程。
        
        Returns:
            宽表 DataFrame，index=[ts, symbol]，columns=[归母净利润, ROE, ...]
        """
```

## 六、关键设计决策

### 6.1 为什么不用 BaoStock 的财务 API？

BaoStock 也提供 `query_profit_data()` / `query_balance_data()` 等财务接口，且文档更完整。但选择 QMT 的理由：

- QMT 已是主数据源（Level 1 行情），统一数据源减少依赖
- QMT 的 `get_financial_data()` 输出格式更接近数据层原有的中文列名体系
- 本地下载后无网络依赖，回测速度更快

**备选方案**：如果 QMT 输出格式不兼容，BaoStock 作为 fallback。

### 6.2 TTM 计算策略

QMT 的 `PershareIndex` 表提供部分指标的直接值（如 `du_return_on_equity` 是 TTM ROE），但不是全部。对于没有直接 TTM 值的字段（如归母净利润），由 `preprocessor` 自行聚合：

```
TTM_np = Q1_np + Q2_np + Q3_np + Q4_np（最近四个季度）
单季同比 = (本季_np - 去年同期_np) / |去年同期_np|
```

### 6.3 PIT（Point-in-Time）合规

防止未来信息泄露的核心机制：

```
财报公告日（announce_time）→ 下一交易日生效

示例：
  3月31日公告 Q4 年报 → 4月1日（或下一交易日）起因子计算可用
  4月30日公告 Q1 季报 → 5月第一个交易日起可用
```

实现方式：对每个 `(symbol, report_period)` 记录，找到 `announce_time` 之后的第一个交易日，将数据从该日起向后填充，直到下一期财报更新。

### 6.4 存储粒度

- 按 `{symbol}/financial.parquet` 存储，每只股票一个文件
- 文件内按报告期（`report_period`）索引
- `meta.json` 记录最后同步日期、字段清单、数据质量标记

### 6.5 增量更新

首次全量拉取后，后续只需下载新增报告期的数据：

```
1. 读取 meta.json → 获取 last_sync_date
2. 调用 download_financial_data(start=last_sync_date)
3. 只处理新增报告期的数据
4. 合并到已有 Parquet
5. 更新 meta.json
```

## 七、API 返回格式确认

### 7.1 `get_financial_data()` 返回格式

```python
from xtquant import xtdata

xtdata.download_financial_data(stock_list, table_list)
data = xtdata.get_financial_data(
    stock_list=["600035.SH"],
    table_list=["Income", "PershareIndex"],
    start_time="20240101",
    end_time="20251231",
    report_type="report_time"
)
# → {stock: {table: DataFrame}}
# DataFrame 列名为英文字段，含 m_anntime（披露日期）和 m_timetag（截止日期）
```

### 7.2 QMT 字段 → 数据层输出列 完整映射（已确认）

| 输出列 | QMT 表 | QMT 英文字段 | 说明 |
|------------|--------|------------|------|
| `归母净利润` | Income | `net_profit_excl_min_int_inc` | 单季值，preprocessor 自行聚合 TTM |
| `归母净利润同比` | PershareIndex | `inc_net_profit_rate` | ⚡ **预计算值，直接可用** |
| `ROE` | PershareIndex | `du_return_on_equity` | TTM 值，直接可用 |
| `ROE_np_单季` | — | Income 归母净利 / Balance 净资产 | 需 preprocessor 自行计算 |
| `净资产` | Balance | 总权益字段 | 用于 BP 因子 |
| `自由现金流` | CashFlow | OCF - CAPEX | 需自行计算（字段见下方 CashFlow 表） |
| `净利润率` | PershareIndex | `net_profit` | ⚡ **预计算值，直接可用** |
| `营业总收入` | Income | `revenue` | 用于个别策略 |
| `红利因子` | — | `xtdata.get_divid_factors()` 的 `interest` 字段 | ⚡ **每股股利（税前，元）**，非 PershareIndex |

### 7.4 分红数据的来源

**不在 PershareIndex 中。** 来自 `xtdata.get_divid_factors()`，该 API 当前已用于复权因子获取（`QMTConnector.query_adjust_factor()`）。返回值包含字段：

| 字段 | 含义 |
|------|------|
| `interest` | **每股股利（税前，元）** ← 这就是红利因子需要的 |
| `stockBonus` | 每股红股 |
| `stockGift` | 每股转增股本 |
| `dr` | 除权系数 |

> 只需在现有 `query_adjust_factor()` 调用中额外读取 `interest` 列，无需新 API。

## 八、不涉及的范围

- **不修改** `QMTConnector`：Level 1+2 行情接口不变
- **不修改**策略层代码：策略继续从 `df.columns` 读取中文字段名，预处理层负责注入
- **不新建** 策略：本模块只提供数据管道，不涉及策略逻辑
- **不覆盖** 实时财务数据：仅处理历史财报（季报/年报），实时公告解析不在范围内
