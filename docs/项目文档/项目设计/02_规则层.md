# 01_规则层设计

规则模块位于 `app/rule/`，包含 A 股交易规则和上市公司行为规则两大类。

> **依赖说明**：规则层本身不包含数据（行情、持仓、现金），所有数据由调用方（如引擎）以参数形式传入。

---

## 零、架构概览

规则模块采用 **策略模式 + 职责链模式**：

- **`Rule` 抽象基类**：定义规则接口，支持单一规则验证
- **`RuleChain` 类**：将多个规则串联成链，支持批量验证
- **规则类**：如 `LotRule`、`PriceLimitRule` 等，实现具体验证逻辑
- **`TradingRules` 类**：提供底层规则计算（涨跌停、价格笼子等），供规则类调用

```
调用方
    │
    ▼
RuleChain.validate()
    │
    ├──► LotRule.validate()      ──► RuleResult
    │
    ├──► OrderQuantityRule.validate()  ──► RuleResult
    │
    ├──► PriceTickRule.validate()       ──► RuleResult
    │
    ├──► PriceLimitRule.validate()      ──► RuleResult
    │
    └──► PriceCageRule.validate()        ──► RuleResult
```

## 一、A 股交易规则 (`trading/`)

交易规则模块拆分为三个文件：

| 文件 | 职责 |
|------|------|
| `board.py` | 板块配置（Board/BoardConfig/PriceLimit）、板块识别（get_board） |
| `calculator.py` | TradingRules 核心计算 + ASHARE_RULES 单例 |
| `validators.py` | 6 个 Rule 子类适配器，供 RuleChain 使用 |

### 1.1 板块配置

| 板块 | 代码范围 | 整手股数 | 最小委托 | 限价单上限 | 市价单上限 | 零股支持 | 涨跌停 |
|------|----------|----------|----------|------------|------------|----------|--------|
| 主板 (MAIN) | 600xxx, 000xxx, 001xxx, 002xxx | 100 | 100 | 100万股 | 5万股 | ❌ | ±10% |
| 创业板 (GEM) | 300xxx, 301xxx | 100 | 100 | 100万股 | 5万股 | ❌ | ±20% |
| 科创板 (STAR) | 688xxx, 689xxx | 200 | 200 | 10万股 | 5万股 | ✅ | ±20% |
| 北交所 (BSE) | 430xxx, 830xxx | 100 | 100 | 100万股 | 5万股 | ✅ | ±30% |

### 1.2 整手与零股规则

- **买入**: 必须为整手的整数倍（科创板/北交所支持整手+零股）
- **卖出**: 主板/创业板支持"零股全卖"（一次性卖出全部零散持仓）
- **零股全卖**: 当卖出数量等于当前持仓时，无论是否为整手均视为合法

### 1.3 价格规则

#### 价格跳动 (Price Tick)
- A 股股票统一为 **0.01 元**

#### 涨跌停板

| 类型 | 主板/创业板 | 科创板/北交所 |
|------|------------|--------------|
| 普通股票 | ±10% | ±20% |
| ST 股票 | ±5% | ±20% |
| 新股首日 | ±44% | 无 |

#### 价格笼子 (有效申报价格范围)

| 板块 | 买入 | 卖出 |
|------|------|------|
| 主板/创业板 | ±2% 或 ±0.1 元（取较宽者，连续竞价时段生效） | 同买入 |
| 科创板 | 不得超过基准价 ±2% | 不得低于基准价 97% |
| 北交所 | 不得超过基准价 ±5% | 不得低于基准价 95% |

> 注：主板/创业板在集合竞价时段（开盘 9:15-9:25、收盘 14:57-15:00）不适用价格笼子。

### 1.4 核心接口

```python
ASHARE_RULES = TradingRules()

# 委托数量验证
is_valid, reason = ASHARE_RULES.validate_order(
    symbol="600000.SH",
    quantity=100,
    is_market_order=False,
    current_holding=100,
    is_selling=False,
)

# 委托数量处理（取整、裁剪）
rounded_qty = ASHARE_RULES.round_order(
    symbol="600000.SH",
    quantity=150,
    is_market_order=False,
    current_holding=100,
    is_selling=False,
)

# 涨跌停价计算

    symbol="600000.SH",
    pre_close=1055,  # 10.55元 (int ×10⁴)
    is_st=False,
    is_new_listing=False,
)  # → PriceLimit(low=950, high=1160)

# 有效价格范围（涨跌停 + 价格笼子交集）

    symbol="688001.SH",
    pre_close=1000,
    ref_price=1000,
    is_st=False,
    is_new_listing=False,
    order_side="BUY",
    trading_time="continuous",
)
```

## 二、上市公司行为规则 (`corporate/`)

### 2.1 行为类型

| 类型 | 枚举值 | 说明 |
|------|--------|------|
| 现金分红 | `DIVIDEND` | 除息，每股获得 X 元 |
| 送股/红股 | `BONUS` | 除权，每持有 10 股获得 X 股 |
| 配股 | `RIGHTS_ISSUE` | 按配股比例认购新股 |
| 拆股 | `SPLIT` | 1 拆 N，股数增加 |
| 并股 | `MERGE` | N 并 1，股数减少 |

### 2.2 行为数据结构

```python
# 现金分红
DividendAction(
    symbol="600000.SH",
    ex_date=datetime(2024, 6, 15),  # 除息日
    pub_date=datetime(2024, 6, 1),  # 公告日
    event_type=ActionType.DIVIDEND,
    dividend_per_share=0.5,  # 10派5元 → 0.5元/股
)

# 送股
BonusAction(
    symbol="600000.SH",
    ex_date=datetime(2024, 6, 15),
    pub_date=datetime(2024, 6, 1),
    event_type=ActionType.BONUS,
    bonus_ratio=0.5,  # 10送5 → 0.5
)

# 配股
RightsIssueAction(
    symbol="600000.SH",
    ex_date=datetime(2024, 6, 15),
    pub_date=datetime(2024, 6, 1),
    event_type=ActionType.RIGHTS_ISSUE,
    subscription_price=8.0,  # 配股价 8 元
    ratio=0.3,  # 10配3 → 0.3
    is_renounceable=True,  # 可放弃
)

# 拆股
SplitAction(
    symbol="600000.SH",
    ex_date=datetime(2024, 6, 15),
    pub_date=datetime(2024, 6, 1),
    event_type=ActionType.SPLIT,
    split_ratio=2.0,  # 1拆2
)
```

### 2.3 行为处理规则

#### 现金分红
- 现金增加 = `持仓股数 × 每股分红金额`
- 持仓数量不变
- 成本均价不变（分红不改变成本）

#### 送股
- 新增股数 = `持仓股数 × 送股比例`
- 现金不变
- 成本均摊：总成本不变，股数增加，单位成本下降

#### 配股
- 可认购股数 = `持仓股数 × 配股比例`
- 认购资金 = `可认购股数 × 配股价`
- 若资金不足，自动放弃配股
- 配股后成本增加（以认购价买入新股）

#### 拆股
- 新股数 = `原股数 × 拆股比例`
- 成本均摊

#### 并股
- 新股数 = `原股数 // 并股比例`（通常按整数处理，余数可能现金补偿）
- 成本均摊：总成本不变，股数减少，单位成本上升

### 2.4 核心接口

```python
processor = CorporateActionProcessor()

# 注册处理器（可自定义）
processor.register(ActionType.DIVIDEND, DividendProcessor())
processor.register(ActionType.BONUS, BonusProcessor())
processor.register(ActionType.RIGHTS_ISSUE, RightsIssueProcessor(auto_subscribe=True))
processor.register(ActionType.SPLIT, SplitProcessor())

# 处理行为
result = processor.process(
    action=dividend_action,
    quantity=1000,  # 持仓 1000 股
    cost_basis=105500,  # 成本 10.55 元 × 1000 股 (int ×10⁴)
    available_cash=50000,  # 可用资金 5 万元 (int ×10⁴)
)

# ActionResult
result.success  # True/False
result.quantity_change  # 股数变化
result.cash_change  # 现金变化 (int ×10⁴)
result.cost_basis_change  # 成本变化
result.message  # 处理说明
```

## 三、市价单规则

### 3.1 市价申报特点

- **数量限制**：市价单单笔申报上限为 **5 万股**（所有板块一致）
- **保护限价**：科创板/北交所市价单必须包含保护限价，主板/创业板市价单也需输入保护限价
  - 买入：委托价格不超过保护限价
  - 卖出：委托价格不低于保护限价

### 3.2 市价单验证接口

```python
is_valid, reason = ASHARE_RULES.validate_market_order(
    symbol="688001.SH",
    quantity=3000,
    side="BUY",
    protection_price=1050,  # 保护限价 10.50 元 (int ×10⁴)
)
```

## 四、金额单位说明

规则模块内部统一使用 `int × 10⁴` 表示金额，即：
- `105500` 表示 `10.55 元`
- `10000` 表示 `1 元`

这样做是为了避免浮点数精度问题。

## 五、使用注意事项

### 5.1 除权除息日调整时机

`CorporateActionProcessor.process()` 应该在 **除权除息日（ex_date）的开盘前** 调用，具体在回测引擎的 `on_before_trading` 事件中执行。

原因：
- 回测中：需要在当日开盘前调整持仓股数和现金
- 实盘中：交易所会在该日直接调整持仓和账户余额（分红现金到账日可能晚于除息日，但开盘价已反映调整）

### 5.2 前收盘价与复权

`get_price_limit()` 传入的 `pre_close` **必须是经过复权调整后的昨收价**（前复权或后复权均可，但必须与行情数据一致）。

规则模块不负责复权处理，此工作应由数据模块完成。

### 5.3 价格笼子基准价

`get_valid_price_range()` 中的 `ref_price` 参数应由调用方根据当前盘口计算：

| 申报方向 | 基准价确定方式 |
|----------|---------------|
| 买入 | 卖一价（若无卖一，则用最新成交价或昨收） |
| 卖出 | 买一价（若无买一，则用最新成交价或昨收） |

具体逻辑由订单管理模块负责计算，规则模块仅验证价格是否在笼子范围内。

### 5.4 配股认购资金处理

| 场景 | 处理方式 |
|------|----------|
| 回测 | 可设置 `auto_subscribe=True` 自动认购（简化处理） |
| 实盘 | 应检查 `available_cash`，若不足则返回 `success=False`，消息如"配股资金不足，已放弃"，引擎根据结果记录日志或触发告警 |

### 5.5 性能优化

- **规则对象应为无状态单例**：避免重复创建规则实例
- **计算结果可缓存**：价格跳动、涨跌停等计算在同一股票同一天内不变，可缓存结果避免重复计算

### 5.6 引擎交互示例

```python
# 引擎中验证订单
def validate_order(self, order: dict, context: dict) -> bool:
    chain = create_order_validation_chain(
        rules=ASHARE_RULES,
        symbol=order["symbol"],
        quantity=order["quantity"],
        is_market_order=order.get("is_market_order", False),
        is_selling=order["side"] == "SELL",
        current_holding=context.get("holding", 0),
    )
    all_valid, results = chain.validate(
        symbol=order["symbol"],
        quantity=order["quantity"],
    )
    if not all_valid:
        for r in results:
            if not r.is_valid:
                self.logger.warning(f"订单校验失败: {r.message}")
        return False
    return True
```
